# Olesia Frient (LILETTI) — Engineering Report to "Fully Functional"

> Generated by multi-agent audit (8 finder dimensions × adversarial verification). 53 verified findings. Payment integration intentionally excluded.

## 1. Executive Summary

The storefront and admin are feature-complete in scaffolding but broken in three load-bearing places: **guest checkout is hard-blocked by the API** (every guest order 400s), **single-entity store fetchers crash pages on any API hiccup** (category/product/colors/sizes), and the **admin API has a multi-tenant authorization hole** (cross-store update/delete/read by ID). Beyond those blockers, several built pages render empty because **no narrative/social-proof/FAQ/blog data is seeded**, and a handful of features are stubbed (product search, order/custom-order/subscriber deletion, custom-order emails). The remaining items are SEO/i18n polish (wrong canonical domain, hardcoded home metadata, empty alt text). Translation parity is clean across all locales.

## 2. Critical & High Blockers

### Checkout / Orders / Reviews (auth flows)

| Title | File | Impact | Fix |
|---|---|---|---|
| **Guest checkout 400s for all guests** (CRITICAL) | `admin/app/api/[storeId]/checkout/route.ts:79-84` | Storefront advertises "Guest checkout: no login required" but API rejects undefined `customerId`. 100% of unauthenticated checkouts fail. | Make `customerId` optional: `if (customerId && (typeof customerId !== "string" || !customerId.trim())) reject`. Schema already allows `customerId String?`. |
| **Guest orders unretrievable** (HIGH) | `admin/app/api/[storeId]/orders/route.ts:62-77`, `store/actions/get-my-orders.tsx` | Guest orders (`customerId: null`) have no retrieval path — my-orders filters by `customerId`, detail endpoint is admin-only. | Return a guest order token at checkout + a lookup endpoint (email + order-ref), or link orders by email. |
| **Guests cannot submit reviews** (HIGH) | `admin/app/api/[storeId]/reviews/route.ts:100-105` | Same `customerId` non-empty-string validation blocks public review submission. | Allow null/undefined `customerId` for public review POSTs. |

### Store data fetchers crash pages (no error handling)

Single-entity/list fetchers lack the `res.ok` + try/catch pattern that `getBlogPost`/`getCategories`/`getProducts` already use. Any 404/5xx/non-JSON crashes the server component (500 instead of graceful fallback).

| Title | File | Fix |
|---|---|---|
| `getCategory` crashes category page (CRITICAL) | `store/actions/get-category.tsx:5-8` | Check `res.ok`, try/catch, return `null`; type → `Promise<Category \| null>`. |
| `getProduct` crashes product page (HIGH) | `store/actions/get-product.tsx:5-8` | Same; return `null` so caller's `notFound()` fires. |
| `getColors` / `getSizes` crash category filters (HIGH) | `store/actions/get-colors.tsx:5-8`, `store/actions/get-sizes.tsx:5-8` | try/catch + `res.ok`, return `[]`. |
| `getBillboard` (HIGH but **dead code**) | `store/actions/get-billboard.tsx:5-8` | Harden for consistency; unused. |

### Admin API correctness & authorization

| Title | File | Impact | Fix |
|---|---|---|---|
| **Cross-store PATCH (no storeId)** (CRITICAL) | product `[productId]/route.ts:135-138, 165-168`; categories/stats/billboards/content/colors/sizes/faqs `[id]/route.ts` | Authenticated user from store A can modify any resource in store B by ID. | Add `storeId` to every `update`/`updateMany` where clause. |
| **Product validation never returns** (CRITICAL) | `products/route.ts:44-54` (POST), `products/[productId]/route.ts:79-89` (PATCH) | `new NextResponse(...)` without `return` — invalid products are created/updated, corrupting data. Boolean checks should test presence, not falsiness. | Add `return` to all six lines in each handler; fix boolean checks to `=== undefined`. |
| **Individual GET endpoints leak across stores** (HIGH) | products/categories/stats/billboards/colors/sizes/faqs/content `[id]/route.ts` | `findUnique({ where: { id } })` returns any store's resource by ID. | Add `storeId` to where clause. |
| **Cross-store DELETE (no storeId)** (MEDIUM) | same set, deleteMany | Auth check gates store ownership, so not exploitable today — defense-in-depth gap. | Add `storeId` to all `deleteMany` where clauses. |

### Public API leaks unpublished content (server-side `isPublished` filter missing)

Storefront filters client-side via `publishedSorted()`, so not user-visible today, but the API exposes drafts to any direct caller.

- **Blog GET** — `blog/route.ts:23-26` (truthy `?published` check is wrong) **and** `blog/[blogId]/route.ts:22-30` (no filter at all). (HIGH)
- **Stats GET** — `stats/route.ts:82-91`. (HIGH)
- **Content GET** — `content/route.ts:87-95` and `content/[contentId]/route.ts:8-29` (also missing storeId). (MEDIUM/HIGH)
- **FAQs GET** — `faqs/route.ts:85-92`. (MEDIUM)

Fix pattern: `if (!userId) where.isPublished = true`.

### Stubbed core feature

| Title | File | Fix |
|---|---|---|
| **Product search non-functional** (HIGH) | `store/components/search-dialog.tsx:1-77` | Input has no state binding; submit just closes dialog; no backend search. Bind input state, add a search endpoint (or `q` param on products), render results. |

### SEO domain blocker (wrong canonical everywhere)

`NEXT_PUBLIC_SITE_URL` is unset, so fallbacks are always active — and they disagree. Correct domain is **`https://liletti.md`**.

- `store/lib/seo.ts:3` falls back to `liletti.delice.my` (wrong) → corrupts `robots.ts` + sitemap.
- `product/[productId]/page.tsx:23` also `liletti.delice.my` (wrong).
- `atelier/page.tsx:12`, `custom-order/page.tsx:11`, `about/page.tsx:12` use `liletti.md` (right).

**Fix:** centralize `SITE_URL` in `seo.ts` (fallback `https://liletti.md`), import everywhere, set + document `NEXT_PUBLIC_SITE_URL`.

## 6. Recommended Execution Order

1. **Unblock guest checkout** — relax `customerId` validation; add guest order retrieval. Verify end-to-end.
2. **Harden store fetchers** — `res.ok`/try/catch/null-or-`[]` for getCategory, getProduct, getColors, getSizes, getBillboard.
3. **Close admin authz holes** — add `storeId` to all PATCH/DELETE/GET-by-id where clauses; add missing `return`s in product validation; fix booleans; re-enable image validation.
4. **Server-side `isPublished` filtering** — blog (list+detail), stats, content (list+detail+storeId), faqs.
5. **Relax reviews `customerId`** for public submissions.
6. **Seed content** — stats, FAQs, reviews, blog posts, content blocks (i18n + published).
7. **Wire SocialProof** into home page.
8. **Fix SEO domain** — centralize `SITE_URL` → `https://liletti.md`, set + document env.
9. **Implement product search** + backend.
10. **Cart quantity** support.
11. **Admin CRUD parity** — DELETE for orders/custom-orders/subscribers; admin custom-order creation.
12. **Custom-order emails** — confirmation + status-change.
13. **Polish** — home metadata i18n, alt text, duplicate nav, `Category.billboard?`, S3 startup validation, dead-code cleanup.
